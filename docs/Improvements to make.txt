WHAT IS STILL OPEN
==================

Everything already built is documented in README.md. This file is only
the things that are NOT done. Each entry says what is missing and why it
is still missing, so it can be picked up without re-deriving the context.


CONTENT
-------

- 40 subclass feature grants have no source and are listed in
    docs/subclass-text-gaps.md. They are 2024-revision features, or content
    outside the SRD entirely, that no free source carries. Checked and
    rejected: dnd5e.wikidot.com (2014 rules, so no 2024 features at all),
    the 2024 SRD 5.2.1 (one subclass per class - 12 of the 117), D&D Beyond's
    free tier (also SRD-limited), and dnd5eapi (0 name matches for any of
    them).

    They are deliberately left blank rather than paraphrased from memory.
    A plausible-looking invention is worse than an empty cell here, because
    a player cannot tell the difference between the two, and the sourcing
    rules in docs/SUBCLASS-CONTENT-AUDIT-2026-09.md exist to keep invented
    rules out of the data. Sourcing them needs a paid book (the 2024 PHB and
    its expansions) or a store the scraper is allowed to read.

    Four subclasses are empty for the same reason: Path of Wild Magic, Way
    of the Sun Soul, Bladesinging College and Warding Magic.

- Four more grants are one feature the export listed once per level (the
    Monk's three "Additional Elemental Discipline", and a fragment of the
    Arcane Shot options table). There is no second section on any page to
    find; the rule is already sourced under the feature named in the gaps
    doc, and the choices have pickers. Recorded rather than filled, because
    filling them with the first feature's text would misstate the rules.

- Features whose text is now sourced still have their EFFECTS unmodelled.
    The first pass of this is done: every damage resistance a feature
    states unconditionally is recorded, so the sheet now tells the Forge
    Domain you are resistant to fire, the Psi Warrior to psychic, the
    Fathomless to cold, and so on. See SOURCED_RESISTANCES in
    js/data/contentFixups.js, which is checked against the fetched text at
    runtime and adds nothing if the text stops saying so.

    What is left is the long tail of effects that are conditional ("while
    you...", "for 1 minute"), situational, or need a data model the sheet
    does not have yet - companions, auras with a radius, spell reactions.
    That is authoring rather than sourcing, and there is no finite list of
    it the way there was for the text.

    Every feature that defines a choice has a working picker (38 across 28
    subclasses - see js/data/subclassPicks.js), and
    scripts/audit-subclass-choices.mjs reports 0 build choices without one.
    It classifies choice-bearing prose so a play-time target ("one or more
    creatures of your choice") is never mistaken for a saved build pick.

- Races and classes need nothing here. All 36 race grants and all 226
    class grants carry text, and the short ones are values, not missing
    prose - a Hit Die of "d12" and a Speed of "30 ft. walking" are the
    complete answer for those rows.


ACCESSIBILITY
-------------

- A dyslexia-friendly font option.
    Nothing in the app changes the reading font for prose. The sheet uses
    one body font throughout. The honest version is a toggle that swaps
    --font-body (and ideally a slightly taller line-height, which is
    usually what actually helps) for a face designed for it.

- A colour-blind-safe palette.
    Seven themes exist and the palette is entirely tokenised, so a new
    theme is a data entry in js/data/themes.js - but none of the seven was
    designed against a colour-vision deficiency, and nothing tests them
    for contrast ratios. Both halves are open: a palette chosen on purpose,
    and a check that the text/background pairs actually pass.


AUTHORING TOOLS
---------------

- The bundle and catalog library editors have no choice-group UI.
    A bundle's choiceGroups - the things that become a picker in the wizard
    - can only be authored by hand-editing the JSON that gets imported.
    The editors cover entries, field types, metadata and portraits well,
    and simply skip the groups.

    A group editor needs: a row per group, its label, min/max selections,
    level gate, category, and an option list where each option's name,
    description, and the statModifiers/featureGrants it grants are all
    editable. That is the last piece of the content pipeline that is
    JSON-only.

- The wizards' "+1 to any two of these" style choices are still narrow.
    A flexible ASI ("+2 to one, +1 to another" / "+1 to three") is
    supported and is a first-class group type. A general
    "distribute N points across any of these six" is not, and neither is
    a per-option conditional ("choose a skill OR a tool"). One
    skill-or-language group shows the shape, but it is hand-built rather
    than something a bundle declares.


FUTURE
------

- DM campaigns.
    Campaigns with invitations binding several characters together, so a
    DM can see the party and share a sheet with it. Nothing exists yet;
    every character stands alone and sharing is per-character by owner.


ALSO WORTH KNOWING
------------------

- removalConditions is modelled and carried through
    js/render/sheet/levelingModel.js, but nothing populates it. No source
    data shape expresses a removal - the only removal-like data today is
    a pack gate, which is an absence rather than a removal condition. The
    field is honestly empty rather than guessed at. If a content source
    ever expresses "you lose this", that is where it goes.

- No feat icon art. All 83 catalog entries ship with empty imageData
    (compiled from a text export), so every feat row shows the same
    marker. The slot exists and picks up a real image the moment a
    catalog entry has one; the art is the missing part.

- No importer for outside characters. A character built in another app
    or on paper starts here as a fresh sheet, filled in through the
    creation wizard.
