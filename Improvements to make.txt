UI Polish - Stat elements
- Replace the default, hard-coded block label with a "Label" element
- Replace the default, hard-coded label for Num Fields with a label element
- All elements need to have a label element attached to them by default. This label element must be able to be deleted

UI Polish - LHS List
- In the LHS list, make the default name of an unnamed element be whatever that element type is

UI Polish - Selections
- When something is selected, make it so if the mouse is hovering over that element or something inside of it, the border selection still shows that it's selected
- The border needs to be inside of the selection border. If I select an element, group of elements, or block, I want to be able to see the border as well as the selection border around the border
- Include the little icon, from the Add Element menu, that corresponds with the type of element, to the LHS list (so, for example, if the user places a checkbox, there should also be a checkbox icon for that checkbox element in the LHS list)
- When actively dragging around something, it needs to show the selection color even if the mouse isn't hovering over it
- Add a field to the Style sub-menu that lets the user select the color of the border

UI Polish - Num fields and Labels
- Text in Num Fields and Labels need to be horizontally and vertically center-aligned
- Even when Num Fields or Labels are empty, the cursor needs to be horizontally and vertically center-aligned
- Num Fields and Labels' sizes need to be kept constant regardless of if there is text in the field or not (although, come to think of it, simply changing their built-in labels to a Label element might fix this on its own). Typing more than the label can show should expand the label out
- Pressing return in a label should add another line. Allow word-wrapping (but do not break individual words to wrap. Widen the label if necessary)

UI Polish - Styling Menu
- Remove the text beside the Add Background button that says the name of the file loaded (or if nothing has been loaded). It's plainly obvious what, if anything, has been loaded
- Make 'Bg image' --> 'BG Image' and 'Text color' --> 'Text Color'
- Make sure all buttons and fields are vertically centered with respect to their labels on the left-hand side of the hover menu
- Put a horizontal line separator between the fields that deal with the background, text, and hover selection color

UI Polish - Sizing
- Make it so elements do not stretch past their block. They should be fully contained with their block/grouping

UI Polish - Resizing grab handles
- Make sure the resizing grab handles are behind whatever menus should open in front of them
- Add in resizing grab handles for all 4 corners

UI Polish - Moving elements
- Allow elements to be dragged outside of their stat block, however do not allow them to be placed outside of their stat block (they should just stay where they originally were when the user grabbed them). This is intended for things like dragging over to the LHS list, to the top toolbar to be featured in the character block on the character selection screen, and to be dragged into other menus as needed
- Draw a ghost of an element or block when it is being moved

Useability/Portability
- Format a page to be printed. Ask the user which tabs to print
- Detect aspect ratio of view and adjust accordingly. Also allow the user to specify layouts for common aspect ratios (16:9, 16:10, 4:3, whatever that ratio is that phones use when they're upright, whatever that ratio is that phones use when they're sideways, the ratio that tablets use when upright, the ratio that tablets use when sideways). Also allow the user to make their own aspect ratios. I envision this as a button in the toolbar that the user can select, and it will automatically make the grid into that ratio, and move the blocks to fit on that grid, and then the user can move stuff around from there
- There would also need to be functionality that would automatically take a best guess at resizing
- Also, detect the user's current ratio and make that be the default ratio that the user is designing for
- Also have another version in which stat blocks and their elements are simply laid out as rows (I am envisioning this as a simpler view and a view for small screens). This would also be a top toolbar button (so, it would be a toggle between "2D View" (with stat blocks) and "Simple View" (with rows). If you have a better idea for the button names, you're welcome to just go with them)

NEW FEATURES

Elements
- Add in a tab for selecting feats. I am envisioning this tab as consisting of the following: it would consist of rows that, themselves, consist of (from left to right) a checkbox (no label), an icon for that feat, the name of that feat, and a description for that feat, and the equals sign for what this feat actually modifies. The contents of the formula would be described, in words, on a line below the description line (the description line is for flavor text. The line below the description line is the actual mechanical description). All of this would stretch across a single row. At the top of the element would be the number of feats that the user can choose (this is when leveling. The user should also be able to just toggle feats during play (like if the DM said they could just pick a feat))
- Add in a tab for leveling
	- The tab needs to be two sub-tabs: one for the leveling info at a glance, and one for a walkthrough version
	- Add in an object that adds buffs and debuffs (ie, adds to or subtracts from stats and proficiencies); adds built-in spells, abilities, feats, languages, equipment proficiencies, etc.; and adds access to, or removes access from, options (so, for example, a cleric has access to different spells than a necromancer)
		- This object needs to allow for more than one condition (ie, if someone is both an Orc AND a Rogue, then maybe they have access to specific Orc x Rogue abilities). This will also allow for leveling (ie, if you are a Rogue && Level 3, then you have the following options to choose from (list out options))
	- Need a default tab for leveling info (ie, your character's racial/class/origin abilities, ordered by how they interact with your level)
